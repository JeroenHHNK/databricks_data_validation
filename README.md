# Groundwater data validation — Databricks ↔ git ↔ Streamlit

Replicate groundwater head measurements from the Databricks source, validate them
downstream with the existing Streamlit toolkit, and push the quality-checked result back
as a Delta table — **without ever touching the source data**.

```
gold_prd.hl_grondwaterpeilmeting (READ-ONLY)
   │  ① read + clean to hourly, group by meetreeks_id      databricks/notebooks/01
   ▼
waterkeringbeheer_prd.jvanruitenbeek.source_copy_*          ② immutable per-well Delta copy
   │  ③ export CSVs + commit/push                           databricks/notebooks/02
   ▼
GitHub ──pull──► local IDE  output_databricks/time_series_data/<series>.csv + metadata/object_data.csv
   ▲                │  ④ validate + autoflag + Streamlit review
   │  push          ▼
   └──── output_repository/  (reviewed copies, frozen store schema)
   │  ⑤ pull into Databricks, build validated table         databricks/notebooks/03
   ▼
waterkeringbeheer_prd.jvanruitenbeek.validated_meting  → further analysis / Tarso
```

The design follows [`Pipeline Handover.md`](Pipeline%20Handover.md) §8. Constraints and
grants are in [`DATABRICKS_PERMISSIONS.md`](DATABRICKS_PERMISSIONS.md); the source schema is
in [`DATABRICKS_HANDOFF.md`](DATABRICKS_HANDOFF.md) §2.0.

## Repository layout

| Path | What | Status |
|---|---|---|
| `databricks/` | Notebooks + `lib/` + job config — the new work | **built here** |
| `output_databricks/time_series_data/` | Faithful source replication, one flat `<series>.csv` per well (git-tracked). Replaces `input_data/` + converters | generated by `02` |
| `output_databricks/metadata/object_data.csv` | One combined table: per-series filename, ids, vendor, filter depths, coords | generated by `02` |
| `output_repository/` | Local reviewed copies written back to Delta by `03`; frozen store schema `timestamp,raw_data,gecontroleerd,afgekeurd,note` (git-tracked) | written by validation |
| `output_data/` | Ephemeral validate/plot artifacts | gitignored |
| `data/forcing/` | Committed KNMI forcing (cluster has no egress) | committed |
| `dataval/`, `dashboard/`, `functions/`, `streamlit_app.py` | **Vendored validation toolkit** | ⚠️ **drop in — see below** |

## ⚠️ Vendor the validation toolkit

The validation step (④) reuses the existing on-prem toolkit unchanged. That code is **not**
in this repo yet. Copy these from the on-prem repo into the repo root:

```
dataval/            dashboard/            functions/            streamlit_app.py
cli.py              config.py             validation_functions.py
convert_fugro.py    data_access.py        load_forcings.py
convert_wiertsema.py validation_store.py  load_model.py
convert_knmi.py     plotting.py           plot_functions.py
validate.py         autoflags.py
object_data.py      overview.py
autoflag.py         sensor_stitch.py
_utils.py
```

Then make exactly one adaptation (handover §9): point discovery and `validate` at
`output_databricks/time_series_data/` + `output_databricks/metadata/object_data.csv` instead
of running `convert-fugro`/`convert-wiertsema` on `input_data/`, and write reviewed copies to
`output_repository/`. Leave `validation_store.py` untouched (frozen schema/merge logic).
Merge the on-prem `config/settings.yaml` keys into [`config/settings.yaml`](config/settings.yaml).

Until the toolkit is dropped in, the Databricks replication (①–③) and the validated-table
load (⑤) work on their own; only the local review step depends on it.

## Quickstart

```bash
poetry install                      # after the toolkit is vendored in
# Databricks: add as a Git folder, run the job 00 -> 01 -> 02 (see databricks/README.md)
git pull                            # local IDE gets output_databricks/
dataval validate <dataset> && dataval autoflag
streamlit run streamlit_app.py      # manual review -> writes output_repository/
git add output_repository && git commit -m "review" && git push
# Databricks: pull, run 03_validated_to_delta -> validated_meting
```

See [`databricks/README.md`](databricks/README.md) for the full run order and the Volume
fallback.
